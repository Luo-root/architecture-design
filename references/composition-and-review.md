# 组合性与对抗反例

## 组合设计

1. 按实际变化识别组合轴：入口、业务操作、数据类型、执行器、显示器、存储或通知提供方。不强制所有系统具备所有轴。
2. 找到跨轴共享的不变量和业务服务；入口只投影，不复制授权、状态、事务、错误。没有第二个消费者时也可以定义必要的公开扩展接口，但需说明当前替换/测试/外部契约用途，避免为假想未来泛化。
3. 提供方声明操作版本、输入输出schema、能力与不支持原因。注册表匹配能力，不按固定场景名称分派；显式策略处理多个实现的优先级、选择与冲突。
4. 转换内容、换提供方或换执行上下文不等于无损迁移。显式声明哪些数据可交接、哪些必须重建、哪些权限需重取。
5. 替换对新操作生效；在途工作固定依赖版本，缺失或安全撤销时进入明确阻塞/核对，不静默改用新版。
6. 插件/适配器拥有具体实现，宿主拥有准入、调用身份、公共对象与执行约束；权限清单和独立进程不自动提供操作系统强隔离。
7. 用至少一个新的、非预设用途验证扩展：添加它是否仍需修改核心场景switch、复制业务方法或新增全局特例？若需要，指出缺的是哪个公共契约，不默认造另一平台层。

## 按风险选择反例

| 面 | 构造的反例 | 设计必须给出的结果 |
|---|---|---|
| 多入口 | UI与自动化调用同一操作 | 相同授权、版本、状态与错误语义 |
| 能力缺失 | 提供方不支持某种输入或配置 | 发送前拒绝或明确获准替代，不伪装已处理 |
| 身份 | 两提供方ID重名、请求正文伪造管理员 | 命名空间隔离，可信身份不受正文覆盖 |
| 旧执行 | 旧回调/写者在换代后返回 | 提交处条件校验，保留诊断而不覆盖新事实 |
| 取消 | 原操作结束后旧取消迟到 | 不误伤下一次操作；结果不明则阻断复用 |
| 并行等待 | 两分支等待，一分支批准，另一分支仍在执行 | 等待集合、唤醒去重和停止优先级明确；不整体盲重跑 |
| 双提交 | 内容已写但索引未提交，或反过来 | 恢复扫描有依据，未完成内容不成为正常读取 |
| 外部副作用 | 远端成功、本地超时，用户点重试 | 查询/幂等或人工核对，不把未知当未发生 |
| 版本 | 运行中升级插件/流程/schema | 旧运行锁定兼容版本或显式迁移，禁止偷换 |
| 文件冲突 | 用户编辑器与任务并写同一文件 | 基线冲突可见；应用锁不冒称阻止全部外部写者 |
| 同步 | 两设备同时发布头版本 | 条件提交/冲突，不静默丢一方集合 |
| 删除 | 长离线设备回归、其他设备备份仍引用 | 删除代次/确认与保护关系防复活和误删 |
| 导入 | ID冲突、路径穿越、半提交、缺插件 | 引用闭包重映射，staging与可判定提交，不执行包内代码 |
| 通知 | 两渠道同时审批、禁用一渠道、链接预览抓取 | 原子决定；局部撤销不误伤其他渠道；GET无业务副作用 |
| 生命周期 | 插件崩溃/禁用/卸载，页面关闭 | 宿主收敛在途工作，保留用户数据与修复入口 |
| 容量 | 磁盘满、慢消费者、巨消息、队列积压 | 有界背压和可诊断超限，不假保存、无界占用或静默丢证据 |

只报告能说出触发条件与影响的缺陷；找到已有兜底则反驳该候选，不因“看起来复杂”强行重构。

## 对抗闭环与停机条件

- 固定审查范围、文件版本与问题清单；独立第一轮避免仅让对方复述作者解释。
- 对每个候选要求位置/规则、输入或交错、错误结果、最小修法；找不到路径则降为决策问题，不算已确认缺陷。
- 交换不同意见，记录接受/反驳证据；审查者一致不等于外部协议或运行行为已验证。
- 修复后审查最新基线，并检查修复是否破坏其他入口/提供方；有新增修改则更新覆盖范围。
- 明确本轮停止条件：约定风险范围的缺陷闭合、真实阻塞，或资源预算到达；不要以无尽互审替代可运行探针。
- 总结分开列：已闭合契约、仍有设计缺口、待工程验证、未覆盖。用户要求全量时，不以局部PASS宣称全量完成。
