# 功能契约与实现决策

## 逐功能记录

按功能的独立责任划分条目，不把每个按钮都变成服务，也不把多个独立能力藏进一个“平台负责”。公共契约通过ID引用，功能条目只补差异和关联。

| 项 | 记录内容 | 缺失会造成什么 |
|---|---|---|
| 1 职责与归属 | 功能ID、目标、责任模块、事实源、调用方 | 多个模块争改状态，或无人负责 |
| 2 负责范围 | 输入schema/默认/校验、命令与查询、输出及副作用 | “支持功能”无法落到行为 |
| 3 不负责 | 排除内容、明确不支持或接收模块、用户替代路径 | 责任悬空 |
| 4 交接 | 接口/传输、schema版本、资源与对象版本、可信身份来源、时限、接收方不可用行为 | 交接双方各自理解 |
| 5 执行授权 | 可调用主体、范围、校验时点、预授权/确认、撤权、后台执行意图 | UI与其他入口权限不一致 |
| 6 数据生命周期 | 每类数据的落点、大小/索引、保存确认、更新/保留/导出/删除、清理者 | 无限增长、误删或假保存 |
| 7 失败并发 | 状态与转换、超时/断线/取消、去重键、冲突、所有权代次、部分提交、核对/补偿 | 重复副作用、旧执行覆写新状态 |
| 8 限制验收 | 数值单位/默认/配置范围/超限动作，正常、失败、并发、重启、升级反例及预期 | 无法判断符合设计 |

每条用可观察结果表达；“安全”“高性能”“灵活”“适当重试”不作为契约。确实不适用时写原因，不用N/A掩盖未设计。

## 接口与事实源

- 区分产品对象ID、提供方ID、文件路径、内容摘要、展示名；列命名空间与映射。摘要不自动成为权限或业务身份。
- 命令写清缺省/零值/空值，预期revision、幂等作用域与请求摘要冲突。查询不暗中启动任务或改业务状态。
- 信任上下文由受验证入口注入；来自请求正文的actor、role、approved、owner不能自行获得权力。
- 状态表写终态是否可重开、迟到结果怎么保存；重试与恢复、新运行与原运行分别命名。
- 事件保持单一信封，明确事件身份、对象修订、顺序范围、时间语义、payload版本、游标过期和快照接续水位。
- 错误目录单源，写阶段、类别、可披露细节、结果确定性、重试建议、用户下一步；协议错误与业务错误给出映射。

## 存储决策表

对实际出现的数据类型逐行填，不把示例列表当产品固定全集。至少单独检查：结构化元数据、普通正文、原始大文件、外置内容块、FTS/派生索引、缓存/缩略图、事件/审计、任务与检查点、导入暂存、同步队列、备份清单、秘密/凭据引用、崩溃诊断。每行都要回答为什么放这里、为什么不放别处，以及所属责任模块。

| 数据类别 | 事实源/存储位置 | 入库/外置及阈值 | 关键查询/索引 | 提交与完整性 | 保留/备份/清理 | 超限与故障 |
|---|---|---|---|---|---|---|
| 元数据、普通正文、大文件、事件、检查点、缓存、秘密等实际类型 | 谁拥有 | 不存什么也写明 | 排序/分页/唯一性 | 数据库与外部内容是否同事务 | 引用、历史与保护关系 | 不静默截断唯一原件 |

- 大内容外置：定义写暂存、校验、发布不可变对象、提交索引和崩溃扫描；只有满足内容与索引证据才显示已保存。
- 高频增量：定义批量与背压、异常退出可能丢失范围；避免每个显示片段都提交耐久事务。
- 备份覆盖内容与索引的一致版本，验证可恢复；同步不替代历史备份，不复制活动执行权。
- 清理检查在途操作、历史、备份、离线副本与用户保护；缺权威视图时先不删，显示容量压力。
- 数值是版本化预算，不是永恒政策；默认值附工作负载依据、测量方法、调整责任和风险。

## 技术决策记录

每项用同一结构：

- 决策ID与状态：`DECIDED`（已定可实现方案）/ `PROPOSED`（可替换建议）/ `VERIFY`（需外部或工程证据）/ `BLOCKED`（证据不足前不得开放）。状态不能只写“待定”；VERIFY/BLOCKED必须带责任人、证据、影响范围、失败退出路径和解除条件。
- 决策问题、约束与规模；现有机制和不能满足之处。
- 可行替代与选择理由，避免给每个方案平均篇幅却不选择。
- 具体机制：模块/进程、接口、存储、提交顺序、并发、恢复、版本固定。
- 验证：来源或本地探针、输入、预期、实际结果、证据位置。
- 代价、未覆盖、失败退出路径及触发重审的条件。

## 机制、模式与技术选型记录

算法、设计模式、框架、数据库、协议和运行时分别用稳定 `DEC` ID 记录，至少包含：

| 字段 | 需要写清 |
|---|---|
| 约束与变化点 | 哪个输入规模、正确性、并发、扩展或平台限制逼出这个决策 |
| 机制 | 算法输入/输出与不变量；模式参与者/生命周期；技术的具体模块、版本和接线 |
| 资源与复杂度 | 时间/空间复杂度、典型/上限规模、内存、磁盘、网络、锁和并发影响；初始预算不是性能保证 |
| 替代方案 | 至少一个足以工作的简单替代及放弃理由；模式不是目的 |
| 失败语义 | 结果错误/不完整/未知时的降级、回滚、核对和不可用行为 |
| 兼容与迁移 | schema/wire/API、平台、许可证、版本锁、数据迁移与回退边界 |
| 验证与状态 | 输入样本、正确性/基准/故障测试、证据位置；`DECIDED/PROPOSED/VERIFY/BLOCKED` |

算法附带正确性依据：不变量证明、性质测试、基准或权威算法定义；启发式必须说明误判/漏判，近似必须给误差或停止条件。算法不决定授权和业务成功，除非功能契约显式授权其语义。

模式附带“未使用模式”的理由和最小可替换接口；Factory/Strategy/Adapter/Observer/Event Sourcing 等词不能代替请求、响应、所有权、取消、错误和生命周期契约。组合模式优先在注册表/Port/公共服务中体现，不在场景分支里复制。

## 全量覆盖与变更

维护 `功能ID → 八项定义位置 → 事实源/交接方 → DEC算法/模式/技术ID → 决策ID → 反例/测试ID → 缺口状态`，不能只统计标题存在。
修订关键语义时反查所有消费者，包括UI、自动化、插件、迁移、导出与文档；保留规则ID，删除项说明替代关系。
文档引用有效、命名一致只是静态检查；性能、可恢复性、平台兼容和真实外部交互分别列证据，不互相替代。
